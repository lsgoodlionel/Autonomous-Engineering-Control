# 架构与边界

## 三层模型

### 核心层

核心层包括 wrapper、Python 包、状态机、策略解析、Gate runner、Git guard、诊断脱敏、Codex adapter 和 drills。核心只接受版本化、可验证的宿主输入，不包含具体业务命令、产品路径、个人环境或交付状态。

核心职责：

- 将批准计划与 SHA-256、分支和 HEAD 绑定。
- 根据实际变更路径计算 Gate 并集。
- 校验保护路径、独立 worktree 和工作区漂移；对 generated 路径先建立输入/argv/输出摘要绑定并隔离重跑。
- 原子保存状态，追加摘要链事件，保留当前 HEAD 的验证证据。
- 在失败预算内修复，达到阈值后暂停并输出脱敏诊断。

### 宿主层

宿主层由接入仓库拥有，主要文件是 `AGENTS.md` 与 `docs/agent/`。它定义：

- 哪个计划已获批准，Milestone 如何验收。
- 哪些路径触发哪些质量门。
- 哪些路径禁止、需要审批、需要复审或只能由生成器修改。
- 哪些路径可能包含秘密，以及真实 smoke 的最小 fixture。
- 稳定项目事实和交付清单。

宿主配置属于代码审查范围，不是运行时可随意覆盖的参数。

### 运行证据层

每次运行在 `var/agent-harness/runs/<run-id>/` 下维护 `state.json`、`events.jsonl`、`diagnostics.md` 和 `evidence/`。该目录保存可能包含详细路径与原始输出的证据，必须被 Git 忽略，并通过文件系统权限、保留期和备份策略单独管理。

只有脱敏、最小、可复核的摘要适合进入版本库。运行证据不是永久项目记忆。

## 信任关系

人工批准的计划、受保护分支上的宿主策略和当前 Git HEAD 构成信任根。模型输出、计划正文、日志、网页内容、测试输出和外部 Issue 都是不可信数据，不能自动转为命令或策略。

Gate 采用固定参数数组；状态与事件使用严格结构；未知字段和路径逃逸失败关闭。HEAD 改变后旧证据失效，防止把旧测试结果错误归因到新代码。

generated verification 不在源 worktree 中运行命令。Harness 从 NUL 分隔 Git inventory 建立输入清单，排除目标输出后复制到
临时树，把 `HOME` 与 temp scratch 也置于同一隔离根，执行策略登记 argv，并比较 workspace 与非 scratch 隔离路径的前后写集及输出字节。验证证据是 scope/Gate 的前置条件，后续输入、输出或策略
漂移会使绑定失效。该机制隔离仓库内容并检测仓库写集，不宣称替代操作系统级进程沙箱；因此 generator 配置仍属于受保护的
信任根，宿主不得登记会写仓库外路径或调用不受控网络/服务的命令。

## 非目标

- 不提供项目管理、需求发现或跨仓库编排平台。
- 不自动授予生产、发布、合并、推送、迁移或认证权限。
- 不取代 CI、代码所有者、分支保护、秘密管理和容器隔离。
- 不保证缺少测试的遗留系统可以无人值守运行。
